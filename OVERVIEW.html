Shotline

An Omarchy plugin. It captures a walkthrough of an app one step at a time, comments every step right away and files the series into an agent directory as HTML plus Markdown. The matching prompt for the AI agent ends up in the clipboard.

Workflow

1

Pick a region

SUPER + SHIFT + K freezes the screen. The size of the selection sits in the frame while you drag. A click grabs the whole window. Tab cycles through windows, Return takes the highlighted one, Ctrl+Return the whole screen.

2

Type the comment

An input field appears right away. The prompt carries the size of the region, so there is no doubt about what you captured.

3

Annotate if needed

As soon as a shot exists, the pen shows up in the bar. One click opens the image in the editor: the brush to highlight, blur to hide. Enter saves, and the comment dialog comes back.

4

Next step

Back to the app, same key. The bar widget keeps the count. SUPER + SHIFT + U discards the last shot.

5

File it away

SUPER + SHIFT + L asks for title and target folder, renders the series and puts the agent prompt into the clipboard.

The menu (SUPER + SHIFT + I or right click) offers only what is possible right now: next shot, annotate last, blur out last, discard last, finish series, discard series, open last result. It uses the Omarchy menu dialog, so it follows the theme and is keyboard driven.

What mattered while building it

  • HiDPI: the selection measures logical pixels, the PNG holds more. Both sizes end up in the result, because the image is what the agent sees.
  • Sleeping screen: grim waits forever for a frame. The plugin wakes the screen and gives up after 20 seconds with a clear message.
  • Hyprland with Lua: hyprctl dispatch dpms on fails on Omarchy 4. It takes hyprctl eval 'hl.dispatch(hl.dsp.dpms("on"))', with a fallback to the old form.
  • Not losing captures: finish copies into the target first and cleans up afterwards. A failure along the way destroys nothing.
  • Keyboard control: Omarchy binds Tab and Return to slurp's selection layer, no matter who started slurp. The keys leave nothing but a marker file and end slurp; Shotline reads those markers and yields the same selection as the Omarchy tool.
  • From the real test run: four bugs only surfaced in practice: a relative target path landed unresolved in the agent prompt, the prompt read "1 Screenshots", a shortened file name ended in a hyphen, and window detection reached into other workspaces. All four are fixed and covered by tests.
  • Bar glyphs: Nerd Font characters belong in the QML file as "\uf030". As raw characters they do not survive a rewrite, and the button stays empty.
  • Plugin reload: the plugin hangs in the Omarchy plugin folder as a symlink. The auto reload does not follow the symlink: after QML changes, run omarchy-restart-shell.
  • Editor: annotating uses tensaku, Omarchy's own screenshot editor. It saves back into the same file. If it crops, the image size is measured again.
  • Choosing keys: SUPER + SHIFT + S, X and M are taken in Omarchy. The installer warns about conflicts and accepts your own keys.
